# AdvertM 面试问题与完整回答

这份文档按面试追问组织。回答时重点讲清楚任务系统、去重、Meta API 编排、dry-run、Catalog/DPA、失败处理和生产化边界。

## 一、项目整体

### 1. AdvertM 是什么项目？

AdvertM 是一个基于 FastAPI 的 Meta/Facebook 广告后端服务。它支持普通素材广告创建任务、Catalog/DPA 商品目录广告、受众选项查询、任务状态查询和统一响应。任务会持久化到 SQLite，并通过 payload hash 做重复请求复用。默认 dry-run，避免误创建真实广告。

### 2. 它解决什么问题？

它解决的是广告自动化创建流程的后端编排问题。直接调用 Meta API 风险比较高，也不方便追踪失败。AdvertM 把广告创建封装成任务，先校验和落库，再后台执行，成功或失败都能查询状态和结果。

### 3. 项目亮点是什么？

亮点包括：

- 异步任务状态持久化。
- 标准化 payload hash 去重。
- dry-run 安全预览。
- Meta Campaign/Ad Set 复用。
- 同名广告重复检测。
- partial failure 结果保存。
- 受众查询和 targeting 构建。
- Catalog/DPA payload 校验、标准化和 mock 兜底。

### 4. 为什么不是普通 CRUD？

普通 CRUD 只是数据库增删改查。这个项目的核心是第三方广告平台集成，包括任务编排、外部 API 调用、幂等去重、部分成功处理、素材图片处理和广告对象层级关系。

### 5. 项目有哪些核心模块？

主要模块：

- API 路由层。
- TaskService 任务服务。
- TaskDao 数据访问层。
- FacebookAdService 普通素材广告编排。
- MetaMarketingApiService Graph API 封装。
- TargetingBuilder 受众和 targeting。
- Catalog payload 校验和 SDK 创建。
- ImageStore 图片保存。

## 二、FastAPI 和响应设计

### 6. 为什么使用 FastAPI？

FastAPI 支持 Pydantic 请求校验、自动 OpenAPI 文档、异步接口和 BackgroundTasks。广告创建请求结构复杂，使用 Pydantic 能提前校验请求；OpenAPI 也方便前端和调用方联调。

### 7. 为什么要统一响应结构？

统一 `code/message/data` 能让前端和调用方用一致方式处理成功和失败。项目还注册了 HTTPException 和 RequestValidationError handler，把框架异常也转换成统一结构。

### 8. 为什么用 BackgroundTasks？

广告创建可能需要多个外部 API 调用，不能让 HTTP 请求一直阻塞。BackgroundTasks 让接口快速返回 task_id，实际创建在后台执行。适合当前轻量单机任务场景。

### 9. BackgroundTasks 有什么边界？

它不是生产级任务队列。进程退出可能丢任务，多实例之间不共享执行调度，也没有重试、延迟任务、并发控制和 worker 监控。生产中可以换 Celery/RQ/Arq 或消息队列。

## 三、任务系统

### 10. 提交广告任务的流程是什么？

`/fb/ad/create` 接收广告 payload，封装成 `TaskSubmitRequest(task_type="fb_ad_create")`，调用 `TaskService.submit_task()`。TaskService 计算 payload hash，查找可复用任务，如果没有则创建新 task 并加入 BackgroundTasks，最后返回 task_id。

### 11. 任务状态有哪些？

有 `pending`、`processing`、`success`、`fail`。提交后是 pending，后台开始执行变 processing，执行成功是 success，异常是 fail。

### 12. 任务为什么要落 SQLite？

落库后客户端可以查询任务状态和结果，服务重启后也能保留历史任务。SQLite 部署简单，适合单机和面试项目。生产多实例要换成 PostgreSQL/MySQL 或独立任务系统。

### 13. 去重怎么实现？

TaskService 会把 params 递归标准化，然后 JSON dump 时排序 key，最后计算 SHA-256。提交任务时按 `task_type + payload_hash + status` 查找已有 `pending/processing/success` 任务，有则直接返回已有 task_id。

### 14. 为什么 `image_base64` 不直接参与 hash？

base64 字段可能很大，直接参与 JSON hash 会让标准化结果很臃肿。项目用 base64 字符串的 SHA-256 摘要代替原文，既能表达图片内容是否相同，又能保持 hash 输入紧凑。

### 15. 为什么失败任务不复用？

失败可能是临时网络问题、Meta 权限问题或参数问题。复用失败任务会让用户无法重试。只复用 pending、processing、success 更合理。

### 16. 任务失败怎么记录？

普通异常会记录 error、message 和 traceback。MetaAdCreationError 会额外带 partial_result，把已经创建的 campaign/adset/creative 等中间结果保存下来，方便排查和人工补偿。

## 四、普通素材广告

### 17. dry-run 是什么？

dry-run 是默认模式，服务只保存任务、处理图片并返回预览，不调用 Meta API 创建真实广告。它用于安全联调，避免测试请求直接消耗预算或创建线上对象。

### 18. 真实创建广告的流程是什么？

关闭 dry-run 后，流程是：校验配置，解析账户和 Page，查找或创建 Campaign，查找或创建 Ad Set，检查同名 Ad，创建 Creative，创建 Ad。所有对象默认 PAUSED。

### 19. 为什么所有对象默认 PAUSED？

广告 API 调用成功后如果直接 ACTIVE，可能立即开始花费预算。默认 PAUSED 是安全设计，创建后需要人工审核或后续明确发布动作。

### 20. 为什么只处理第一个 ad set 和第一个 ad？

这是当前实现边界。请求 schema 支持多个 ad set 和多个 ad，但普通素材真实创建链路目前只处理第一个。面试时要主动说明，后续可以循环处理并定义批量失败策略。

### 21. Campaign / Ad Set 怎么复用？

先查本地历史任务结果，如果找到同账户、同名称的 campaign/adset，就复用；否则查 Meta API；都没有才创建。这样减少重复对象，也减少 API 调用。

### 22. 广告名重复怎么检测？

在创建 Ad 前，先按 account + adset_id + ad_name 查本地历史任务，再查 Meta API。如果存在，就返回 `duplicate_prevented`，不创建新广告。

### 23. 为什么要查本地历史，也要查 Meta API？

本地历史快，可以复用自己创建过的对象；Meta API 能发现不是本系统创建但已经存在的对象。两者结合更稳。

## 五、Meta API

### 24. MetaMarketingApiService 封装了什么？

它封装 Graph API 调用，包括 campaign 查询/创建、adset 查询/创建、ad 查询、creative 创建、ad 创建、账户 ID 解析、Page ID 解析、错误处理。

### 25. 预算为什么要乘 multiplier？

Meta API 通常要求预算使用货币最小单位，比如美元用美分。`META_DEFAULT_CURRENCY_MULTIPLIER=100` 表示用户输入 10，提交给 Meta 是 1000。

### 26. targeting 怎么构建？

默认包含 geo locations。根据 audience 类型，可以构建 interest targeting、复制 saved audience targeting，或者组合 saved audience 和多个 interests。

### 27. 受众查询怎么做？

`/fb/ad/audience/options` 会查询 saved audiences，并按关键词搜索 interests。关键词支持中文逗号、顿号、英文逗号和“或”，还支持中文兴趣名映射到英文。

### 28. Meta API 失败怎么办？

`_post()` 如果发现 HTTP 错误或响应有 error，会抛 RuntimeError。create_ads 捕获异常后包装成 MetaAdCreationError，并带上 partial_result。

## 六、图片处理

### 29. Base64 图片怎么处理？

`persist_payload_images()` 遍历 payload 中所有 ad。如果有 `image_base64`，就解码保存到 `storage/images/{task_id}`；如果只有 `image_url`，不下载，只记录 URL。

### 30. 为什么文件名带 hash？

文件名包含内容 hash，可以降低重复和冲突风险，也方便根据文件名看出内容是否变化。

### 31. 支持 data URL 吗？

支持。`image_store.py` 会识别 `data:image/png;base64,...` 形式，并根据 MIME 映射扩展名。

## 七、Catalog/DPA

### 32. Catalog/DPA 是什么？

Catalog/DPA 是商品目录动态广告，广告素材来自商品目录和 Product Set。它更适合电商商品自动投放，不是普通单图素材广告。

### 33. Catalog validate 做什么？

`/fb/catalog/validate` 校验 payload 必填字段、adsets/ads 类型、预算、年龄、国家、受众 ID、商品组 ID 和 link 格式，并返回标准化后的 payload。

### 34. 标准化做什么？

标准化会去除字符串首尾空格、国家转大写、预算和年龄转整数、清理 ID 外层引号、过滤空 adset 和空 ad。

### 35. Catalog create 怎么处理 SDK 不可用？

如果 `mock_mode=true`，或没有安装 `facebook-business`，或 token map/授权不可用，就返回 mock result。这样前端和调用方可以先联调完整流程。

### 36. Catalog 真实创建流程是什么？

初始化广告账户，创建 campaign，创建 adset，为每个 ad 的 product_group_ids 创建 Product Set，然后创建 creative 和 ad。无 instagram_user_id 时只投 Facebook，有则 Facebook + Instagram。

### 37. mock 兜底有什么风险？

生产中如果 SDK 或授权缺失却返回 mock，可能让调用方误以为真实创建成功。因此生产环境要明确 mock_mode，只在联调环境允许 mock，生产中应直接失败并告警。

## 八、数据库和持久化

### 38. tasks 表字段怎么设计？

包含 task_id、task_type、status、payload_hash、params、result、error、created_at、updated_at、finished_at。params/result 用 JSON 字符串存储，适合保存复杂请求和结果。

### 39. 为什么有 payload_hash 索引？

任务去重需要按 task_type、payload_hash、status 查询。复合索引能加速查找可复用任务。

### 40. SQLite 有什么边界？

SQLite 简单，但不适合多实例高并发写。生产中应使用 PostgreSQL/MySQL，并把后台任务从 FastAPI 进程中拆出去。

## 九、生产化追问

### 41. 这个项目生产化还缺什么？

缺登录鉴权、租户隔离、任务队列、重试机制、限流、监控告警、审计日志、Meta token 加密存储、多实例共享任务调度、系统化测试和发布流程。

### 42. 如何做真正的任务队列？

可以用 Celery/RQ/Arq + Redis，或消息队列。API 只负责创建任务和入队，worker 独立消费任务，支持重试、超时、并发控制和监控。

### 43. 如何处理 Meta 部分成功？

保留 partial_result 是第一步。生产中还要记录每一步状态，提供人工补偿或自动清理，比如创建了 campaign/adset 但 creative 失败，要能重试后续步骤或标记待处理。

### 44. 如何做权限和多租户？

需要用户系统、租户 ID、广告账户授权关系、token 加密存储、接口鉴权和数据隔离。任务查询也必须限制只能查本租户任务。

### 45. 如何做限流？

可以对创建任务接口按用户、租户、广告账户限流，避免短时间提交大量 Meta API 调用。还要考虑 Meta API 自身 rate limit，worker 层也需要限速和重试退避。

### 46. 如何做可观测性？

指标包括任务提交数、成功率、失败率、平均耗时、Meta API 错误码、重复任务命中率、dry-run 比例、Catalog mock 比例、队列积压数。日志要包含 task_id 和 ad_account_id。

### 47. 如何保护 access token？

不要写入 Git，不要明文长期保存在普通文件。生产中应使用 KMS、Secrets Manager 或数据库加密字段，并定期轮换、最小权限授权。

### 48. 为什么真实广告默认 PAUSED？

这是防止误投放和预算消耗的安全设计。自动化系统可以先创建草稿对象，人工确认后再启用。

## 十、简历表达

### 推荐写法一

基于 FastAPI 实现 Meta/Facebook 广告创建后端，支持普通素材广告 dry-run 预览、真实 Graph API 创建、受众查询、Catalog/DPA 校验和商品目录广告创建。

### 推荐写法二

设计 SQLite 持久化异步任务系统，支持任务状态流转、payload hash 去重、结果/错误/traceback 落库和任务状态查询，避免重复提交导致重复创建广告。

### 推荐写法三

封装 Meta Marketing API 编排流程，实现 Campaign/Ad Set 复用、同名 Ad 重复检测、Creative/Ad 创建、PAUSED 安全默认状态、base64 图片落盘和 partial failure 保留。

### 面试一句话

> AdvertM 的价值是把广告创建变成可追踪、可去重、可回溯的任务系统，而不是简单把请求转发给 Meta API。
